老树开新花：利用树莓派1B（ARMv6）与RTL-SDR打造低功耗高稳定APRS IGate接收网关

在业余无线电（HAM）领域，将手头吃灰的早期初代 树莓派 1B（Raspberry Pi 1 Model B） 搭配廉价的 RTL-SDR（RTL2838）电视棒 改造为 7×24 小时无人值守的 144.640 MHz APRS IGate（纯接收互联网网关），是非常经典的 DIY 方案。

然而，树莓派 1B 发布于十余年前，搭载的是单核 700MHz 的 ARMv6 处理器，内存仅 512MB，且主板供电设计存在著名的 自恢复保险丝（Polyfuse）限流瓶颈。在 2026 年的今天，如何在最新的系统环境下避开 ARMv7 NEON 指令集兼容坑（Illegal instruction）、压榨出最大可用内存、降低整机工作电流以保障双 USB 设备（电视棒 + USB 无线网卡）长期不掉线？

本文完整记录了在 树莓派 1B (Rev 2.0) 上基于最新 Raspberry Pi OS Lite (Debian 13 Trixie 32-bit) 源码编译纯正 ARMv6 版 Direwolf 1.8.2、进行硬件级降功耗与显存释放、消除 Root 权限警告、校准经纬度坐标格式、配置 Systemd 守护服务以及保护 MicroSD 卡寿命的全套工程级方案。

一、 树莓派 1B 硬件参数与系统选型（为什么不能刷 Armbian？）

1. 硬件基线参数核查

通过 SSH 登录树莓派执行 grep -E "Revision|Model" /proc/cpuinfo 与 lsusb，可确认本次实战的硬件配置如下：

硬件模块 型号与规格参数 架构与硬件细节说明
主机型号 Raspberry Pi Model B Rev 2 (Revision: 000e) Sony 英国工厂制造，512MB 物理内存（CPU 与 GPU 共享），双层 USB 2.0 接口 + 百兆网口
处理器 (SoC) Broadcom BCM2835 (单核 700MHz) ARM1176JZF-S (armv6l) 32位架构，带 VFPv2 浮点单元（不支持 ARMv7 的 NEON 指令集）
总线与网卡芯片 Microchip (SMSC) LAN9512 (0424:9514 / ec00) 单一 USB 2.0 通道扩展出的内置 USB Hub 与 10/100M 以太网控制器
SDR 接收机 Realtek RTL2838 DVB-T (0bda:2838) RTL2832U 主控 + Rafael Micro R820T2 调谐器 + 28.800MHz 无源晶振
USB 无线网卡 Realtek RTL8188CUS (0bda:8176) 802.11n 1T1R 无线网卡（内核 rtl8192cu 免驱识别）

2. 系统版本选择：为什么树莓派 1B 必须用官方系统而非 Armbian？

  • Armbian 不支持树莓派 1B（架构硬伤）：
    不同于玩客云（晶晨 S805，属于 ARMv7 架构），树莓派 1B 的 BCM2835 属于更早期的 ARMv6 架构。标准 Debian 官方早已放弃对 ARMv6 硬件浮点的支持（标准 Debian 的 armhf 软件包在树莓派 1B 上运行会直接触发 Illegal instruction 非法指令崩溃）。因此 Armbian 从未适配过树莓派 1B。

  • 最佳系统选择——树莓派官方 Raspberry Pi OS Lite (32-bit)：
    树莓派基金会直到 2026 年依然专门维护着针对 ARMv6 硬浮点重新编译的官方软件源。使用官方刷机工具 Raspberry Pi Imager，设备选择 Raspberry Pi 1，系统选择 Raspberry Pi OS (other) -> **Raspberry Pi OS Lite (32-bit)**（无桌面精简版，基于 Debian 13 Trixie），并在刷机设置中提前开启 SSH、预设用户名（如 bg4vrg）与 Asia/Shanghai 时区。

二、 供电瓶颈核算：树莓派 1B + 电视棒 + USB 无线网卡电流分析

在树莓派 1B 上同时挂载 RTL2838 电视棒 和 RTL8188CUS 无线网卡 时，供电稳定性是决定系统能否长期运行的核心。

1. 三大核心硬件的官方工作电流核算

根据各芯片官方数据手册（Datasheet）与实测数据，5V 供电端的工作电流构成如下：

硬件单元 核心芯片 5V 端工作电流 功耗特性说明
1. 树莓派 1B 主板 BCM2835 + LAN9512 450mA ~ 500mA 单核 CPU 高负载约 300mA；板载 LAN9512 芯片即使不插网线也恒定消耗约 150mA~180mA
2. RTL-SDR 电视棒 RTL2832U + R820T2 + AMS1117 270mA ~ 280mA R820T2 高频头开启后约 178mA，加上主控与 AMS1117 线性稳压损耗，电流恒定在 275mA 左右
3. USB 无线网卡 Realtek RTL8188CUS 120mA（日常）~ 190mA（峰值） 监听接收状态约 110mA~120mA；Wi-Fi 连续发射瞬间峰值可达 180mA~190mA
🔥 整机总计电流 — 840mA（常态）~ 970mA（峰值） 处于主板入口自恢复保险丝 F3 的临界过载区！

2. 主板保险丝限制与 Rev 1.0 / Rev 2.0 硬件差异

  1. USB 接口单口限流（Revision: 000e Rev 2.0 已解除）：
    早期树莓派 1B Rev 1.0（Revision: 0002/0003，256MB 内存）在 USB 口旁设有 F1/F2 自恢复保险丝，单口限流仅 140mA，直插电视棒必掉线。而本文使用的 Rev 2.0（000e，512MB 内存） 已取消 F1/F2 改为直通，单口可正常输出 300mA+ 电流。

  2. 主板总入口保险丝 F3 的压降隐患：
    所有树莓派 1B 在背面 Micro-USB 供电口下方均设有一颗绿色贴片自恢复保险丝 **F3**，其持续保持电流（Hold Current）约为 **700mA ~ 750mA**（跳闸电流 1.1A）。当整机同时插着电视棒和 Wi-Fi 网卡、长期工作在 850mA~950mA 时，F3 内阻会发热增大并产生 0.4V ~ 0.7V 的压降，极易导致 USB 总线因电压跌破 4.6V 而发生设备重置或断联。

  3. 严禁带电热插拔：
    树莓派 1B 的 5V 滤波电容较小，开机状态下直接插入电视棒会产生浪涌电流拉低主板电压，导致系统直接断电重启或冲掉无线网卡。务必先执行 poweroff 关机后再插拔电视棒。

2. 重大避坑：为什么不能直接用 apt install direwolf？

在 Debian 13 (Trixie) 仓库中，直接通过 apt install direwolf 安装预编译的 direwolf 1.7 后，启动服务会发现进程不断崩溃重启，查看日志会出现致命报错：

  • 故障根源： 仓库维护者在打包 direwolf 1.7 时开启了针对 ARMv7 处理器的 NEON 浮点指令集优化。而树莓派 1B 的 BCM2835 处理器属于 ARMv6 架构（仅含 VFPv2 浮点单元，无 NEON 硬件）。当 rtl_fm 将音频流送入 Direwolf 开始解码运算时，CPU 遇到无法识别的 NEON 指令就会触发 SIGILL (status=132) 非法指令异常并崩溃。

  • 根治方案： 只通过 apt 安装 rtl-sdr 与编译依赖，在树莓派 1B 本机从源码编译安装 Direwolf 1.8.2（CMake 会自动检测 ARMv6 架构并关闭 NEON，生成 100% 兼容的原生指令）。

2. 经纬度坐标格式避坑：为什么网页图标位置会偏离？

在编写 PBEACON 位置信标时，务必注意 坐标系（WGS-84 vs GCJ-02） 与 度分格式（DD^MM.MM vs 度分秒 DD°MM'SS"） 的换算：

  • 原理剖析： Direwolf 配置文件要求的是 “度 + 十进制小数分（DD^MM.MM）”，而 aprs.fi 网页上鼠标悬停显示的是 “度 + 分 + 秒（DD°MM'SS"）”。

    • 实例验证： 若在配置文件中写入 lat=33^57.18N long=118^22.41E，其中的 .18 分等于 $0.18 \times 60 = 10.8\text{ 秒}\approx 11\text{ 秒}$，.41 分等于 $0.41 \times 60 = 24.6\text{ 秒}\approx 25\text{ 秒}$，因此在网页上会精确显示为 33°57'11" N 118°22'25" E。

    • 换算公式： 如果你手头查到的真实 WGS-84 坐标是度分秒格式（例如北纬 33°57'18"，东经 118°22'41"），必须先将“秒”除以 60 转为小数分（$18 \div 60 = 0.30\text{ 分}$，$41 \div 60 \approx 0.68\text{ 分}$），在配置文件中写成 **lat=33^57.30N long=118^22.68E**，且切勿使用高德/百度地图偏移后的火星坐标（GCJ-02），应直接参考手台 GPS 定位出的真实 WGS-84 坐标。
